# 需求模板

每个新功能开发前必须填写此模板。强制思考清楚再动手，减少返工。

---

| 项目 | 内容 |
|------|------|
| 做什么 | 功能行为描述，贴近实际使用场景 |
| 收益 | 解决什么问题、值不值得做 |
| 代价 | 可选：主要成本/风险 |
| Fallback（兜底） | **默认不做**。旧代码/旧字段/向后兼容直接删，死代码是 bug 源。仅当主路径走不通且用户明确要求时才做 |
| 你的建议/评价 | 实现方对需求本身的独立看法：值不值得做、有无更简做法、风险顾虑 |
| 边界情况 | 关键边界场景及处理方式 |

> **实现细节不上表**：影响范围/文件列表、验收标准、前置依赖由实现方内部把握（验收标准在测试阶段自行对照），不要求用户逐条确认。

---

## 填写示例

### 需求
为 MyList 添加批量状态修改功能

| 项目 | 内容 |
|------|------|
| 做什么 | MyList 视图支持勾选多部番后批量修改状态（想看 → 在看 → 看完） |
| 收益 | 一次把 10 部"想看"改为"在看"，不用逐个点击 |
| 代价 | 多选状态管理 + 批量接口（可选） |
| Fallback | 默认不做；部分条目更新失败时提示失败数量并跳过 |
| 你的建议/评价 | 建议先只做状态批量修改；批量删除风险高，本次不做 |
| 边界情况 | 空选择禁用按钮、跨页全选、网络错误部分失败 |
