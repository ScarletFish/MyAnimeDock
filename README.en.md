## Introduction

**MyAnimeDock** is a Windows-first local anime media library manager. Built for anime enthusiasts who follow seasonal simulcasts while also maintaining a local archive of completed series, it covers the full lifecycle from file import to completion records.

Just point it to your anime folders — MyAnimeDock handles the rest: automatic video file scanning, title and season parsing via [anitomy](https://github.com/Scinath/node-anitomy), metadata fetching from [Bangumi](https://bgm.tv) (covers, synopses, ratings, cast), episode progress tracking via the mpv player, and completion notes with ratings.

> [!IMPORTANT]
> **Requires [mpv](https://mpv.io) player**. MyAnimeDock does not include a built-in player — you need to install mpv separately. We recommend the [hooke007/MPV_lazy](https://github.com/hooke007/MPV_lazy) Windows integration pack for a ready-to-use setup.
>
> All data (library, play records, configuration) is stored locally in SQLite — no cloud dependency. The desktop shell runs on Tauri v2 (Rust sidecar), currently supporting Windows 10+ only.

## Design Philosophy

Most anime management tools are either bloated or heavily cloud-dependent. MyAnimeDock is built around these principles:

| Principle | Description |
|-----------|-------------|
| **Local-First** | All data stays in local SQLite — no account needed, no cloud sync |
| **Player Relay** | We only launch the player and track progress via IPC; playback quality is entirely the player's responsibility |
| **Zero-Config Parsing** | Drop in your anime folders — title, season, and subtitle group are auto-detected regardless of naming convention |
| **Full Lifecycle** | From scan → import → metadata matching → watch tracking → status management, one tool covers it all |
| **Desktop-Native** | Native desktop app — no web server deployment overhead, no bundler build steps |

## Features

### 📁 Smart Scanning

Recursively walks your media directory, auto-detects video files (`.mkv` / `.mp4` / `.avi` / `.mov` / `.webm`), and parses folder names using anitomy to extract title, season, and subtitle group. Supports common naming patterns:

```
[SubGroup] Anime Title S01
Anime Title/Season 1
[VCB-Studio] Another Title [Ma10p_1080p]
```

Falls back to regex-based cleaning on parse failure. Non-episode videos (NCOP, NCED, PV, etc.) are automatically excluded.

When a folder name contains a `[bgmN]` Bangumi ID, the entry is matched automatically without manual search.

![Discovery & Scan page](images/README/discovery.png)

### 🏷️ Metadata Matching

- Automatic cover art, synopsis, rating, tags, and cast information from the Bangumi API
- **Batch Matching Workbench**: list + slide-in panel layout, SSE streaming progress with cancel and retry support
- Sorensen-Dice fuzzy matching algorithm for automatic local-to-Bangumi association
- AniList GraphQL for supplementary romaji title and season chain extraction

### 🏠 Library Dashboard

The library is the default startup view, with a dashboard panel at the top and status-grouped anime grids below:

**Stats Overview** — A single row showing 6 aggregate metrics: total file size, file count, currently watching, completed, total local titles, episodes watched, and watch time.

**Continue Watching** — A horizontally scrollable card list showing in-progress anime (up to 10), sorted by recent activity. Each card displays:
- Video thumbnail (generated by ffmpeg at the playback position) and episode title
- Next episode index / total episodes
- "Continue Playing" button linking directly to the detail page

**Local Library** — Three card grids grouped by MyList status:

| Group | Description |
|-------|-------------|
| Watching | Currently airing series |
| Wishlist | Plan to watch |
| Completed | Finished series |

Each group has a title and count. Cards beyond the viewport fade in with animation. Right-click context menu provides copy title, open on Bangumi, change status, and remove options.

### ▶️ mpv Playback & Progress Tracking

Configure the mpv executable path in settings to get started. We only launch mpv and track progress via IPC; the playback experience (rendering, shaders, interpolation, subtitle styling) is entirely determined by mpv itself.

Playback features:
- Real-time progress tracking via `--input-ipc-server` IPC pipe
- Progress written to SQLite every 10 seconds, with final flush on mpv close
- Watching episode N auto-marks episodes 1 through N-1 as watched
- Resume playback from last position
- Server maintains `activePlays` Map for live session tracking

### 📋 MyList — Status Management Hub

MyList is a dedicated management view covering the full status lifecycle:

```
Import ──→ watching ──→ complete ──→ completed
                                          │
                                    optional ──→ delete
```

**View & Interaction**:

- **Tab Filtering**: Top tab bar filters by status (All / Watching / Wishlist / Completed / On Hold / Dropped), with real-time grid filtering
- **Overview Mode**: Shows all entries grouped by status (Watching → Wishlist → Completed → On Hold → Dropped), each with title and count
- **Card Interaction**: Library entries link to detail page with GSAP Flip cover animation; pure wishlist entries show a detail modal linking to Bangumi
- **Right-Click Menu**: Copy title, open on Bangumi, change status, remove from list

**Status Edit Modal**:

Click the status badge on any card to open the full editor:
- **Status**: Custom dropdown for all 5 states
- **Rating**: Numeric stepper (0–10, 0.5 steps)
- **Progress**: Numeric stepper (episodes watched)
- **Start/End Dates**: Three-segment input (year/month/day) with auto-advance
- **Notes**: Free-text field
- Auto-syncs to MyList and library on save

**Completion Records**:
`completed` entries support a modal for writing ratings, thoughts, and detailed notes, persisted on save.

### 📈 Statistics Page (Stats)

A dedicated analytics page with four D3.js + WordCloud charts:

| Chart | Data Source | Description |
|-------|-------------|-------------|
| **Tag Cloud** | `/api/stats/tags` | Bangumi tag frequency, up to 60 words, weighted rendering |
| **Watch Activity** | `/api/stats/watch-activity` | Area + bar chart overlay, monthly watch time in hours on hover |
| **Rating Distribution** | `/api/stats/ratings` | Histogram of rating ranges with count and percentage |
| **Season Distribution** | `/api/stats/seasons` | Horizontal bar chart for Spring/Summer/Fall/Winter distribution |

Charts automatically adapt to dark/light mode and the current color theme.

![Statistics dashboard](images/README/stats.png)

### 🎨 Theme System

6 color themes with independent dark/light mode, switchable instantly from the bottom dock:

| Theme | Hue |
|-------|-----|
| default | Rose red |
| amber | Warm orange amber |
| ocean | Blue-cyan ocean |
| sakura | Pink-purple cherry blossom |
| emerald | Turquoise emerald |
| violet | Purple violet |

### 🔄 Bangumi OAuth Sync

- OAuth2 login — Pull (fetch collection list) → Merge (with local data) → Push (back to Bangumi)
- Full sync with automatic state change propagation

### 🚀 Auto Import on Startup

On server startup, new folders with `[bgmN]` identifiers are asynchronously scanned and auto-imported through the entire pipeline.

### 🔍 Pinyin Search

The frontend searches across `title`, `bangumiTitle`, and `pinyinTitle` simultaneously, supporting full Pinyin matching (without tone marks).

## Quick Start

### Installation (Recommended)

Download the MSI or NSIS installer from [Releases](https://github.com/user/MyAnimeDock/releases) and double-click to install. Requires Windows 10+ (WebView2 is built-in).

### Running from Source

```bash
# Prerequisites: Node.js 18+, Rust MSVC toolchain, mpv
git clone https://github.com/user/MyAnimeDock.git
cd MyAnimeDock
npm install
cd server && npm install && cd ..
npm run prisma:generate
```

```bash
# Start development mode
npm run dev:server:watch   # Terminal 1: backend (nodemon auto-reload)
npm run dev:tauri           # Terminal 2: Tauri window
# Or start both with a single command
npm run dev
```

## Typical Workflow

### From Download to Completion

```
Download ──→ Set Media Directory ──→ Scan ──→ Import ──→ Metadata Match ──→ Watch ──→ Complete
```

**Step 1: Set Media Directory**

Open settings and choose your anime root folder. Nested directory structures are fully supported.

**Step 2: Scan**

Switch to the Discovery page and click "Scan Directory." All folders containing video files are displayed as a flat card list, each showing title, season, file count, and size.

Already-imported items are marked `alreadyImported`, excluded items are marked `excluded` — no duplicate operations.

**Step 3: Import**

Select the entries you want and click "Import." The system automatically creates library records and a MyList entry (default status: `watching`).

**Step 4: Metadata Matching**

Matching starts automatically after import. The batch matching workbench shows real-time progress, allowing manual correction or retry of failed items.

**Step 5: Watch**

Click an anime cover to enter the detail page — view full metadata (cover, synopsis, rating, cast), select an episode, and play via mpv.

Playback progress is tracked automatically and persisted on mpv close. Each episode card shows its watch status (orange = in progress, green = completed).

**Step 6: Complete**

After finishing, the MyList status auto-switches to `completed`, where you can write ratings and notes. Completed entries can optionally be deleted from the library to keep it tidy — MyList records are preserved.

## Configuration

### Config Files

The following files reside in the server data directory (`server/` in development mode, `%APPDATA%/com.myanimedock.app/` in production):

| File | Description |
|------|-------------|
| `config.json` | User configuration (editable via settings UI) |
| `anime.db` | SQLite database (Prisma ORM) |
| `scanned-tree.json` | Scan tree cache (JSON) |
| `covers/` | Cover image cache |
| `thumbs/` | Video thumbnail cache |

### Configuration Options

```json
{
  "mediaDir": "D:/Media/Anime",
  "playerMode": "mpv",
  "mpvPath": "mpv",
  "theme": "ocean",
  "themeMode": "dark",
  "autoMarkWatched": true,
  "reduceMotion": false,
  "uiScale": 1.25,
  "apiSources": [
    { "type": "bangumi", "url": "https://api.bangumi.lol", "key": "" }
  ]
}
```

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `mediaDir` | string | `""` | Root directory for anime media files |
| `playerMode` | string | `"mpv"` | Player mode (fixed to mpv) |
| `mpvPath` | string | `"mpv"` | mpv executable path or command name |
| `theme` | string | `"default"` | Color theme |
| `themeMode` | string | `"dark"` | Dark/light mode |
| `autoMarkWatched` | bool | `true` | Auto-mark episodes as watched after playback |
| `reduceMotion` | bool | `false` | Reduce animation effects |
| `uiScale` | number | `1.25` | UI scaling factor (shown as % in frontend, range 75–150) |
| `apiSources` | array | `[{...}]` | Metadata source list (type/url/key) |

### Media Folder Structure

```
media/
├── [SubGroup] Anime Title/
├── [VCB-Studio] Another Title S2 [Ma10p_1080p]/
├── Anime Title [bgm12345]/
└── Some Title/Season 1/
```

Unlimited folder nesting — leaf nodes (directories directly containing video files) are recognized as individual entries.

| Tier 3 | `npm run build` | ~5min | Final packaging |

### Common Commands

```bash
npm run dev                  # Start backend + Tauri simultaneously
npm run dev:server           # Start backend only (node server/server.js)
npm run dev:server:watch     # Backend + nodemon auto-reload
npm run dev:tauri            # Start Tauri dev window only
npm run prisma:generate      # Regenerate Prisma client
npm run prisma:migrate       # Create/apply database migrations
npm run prisma:studio        # Open Prisma Studio (SQLite browser)
cd server && npm test        # Run integration tests (17 tests)
```

### Frontend Conventions

- `camelCase` naming, 2-space indentation
- Default startup view is the library
- HTML events use `onclick` attributes (use `addEventListener` for dynamic rendering)
- GSAP registered globally: `gsap.registerPlugin(Flip)`
- CSS scaling via `--scale` custom property — **do not use CSS `zoom`**
- Always check element existence before DOM operations (non-current view returns null from `getElementById`)

### Debugging

Built-in frontend diagnostics: open the console (F12) and run `__debug.toggle()` to enable logging for tracking view switches, scroll positions, and data loading.

```js
__debug.toggle()              // Enable/disable logging
__debug.log(tag, ...args)     // Tagged log output
__debug.snapshot(label)       // Snapshot: view, scrollTop, data length, etc.
```

### Data Persistence

```
User action → API endpoint → targeted write to SQLite table → db.js wrapper
                 ↓
          JSON files (scannedTree, config as standalone JSON)
```

Each API endpoint writes only the modified table (`saveLibrary()` / `saveMyList()` / `savePlaySessions()` / `updateEpisodeProgress()`), avoiding the full `saveData()` that would trigger unnecessary nodemon restarts.

> [!IMPORTANT]
> Development mode DATA_DIR = `server/`, production mode DATA_DIR = `%APPDATA%/com.myanimedock.app`. The Prisma engine path is specified via the `PRISMA_QUERY_ENGINE_LIBRARY` environment variable.
